**同じ部品を、3つのライブラリが3通りに扱っています。**

| | データグリッド (仮想化・列固定) |
|---|---|

第2回では「業務用の分厚い表を作り始めるとお金が要る」と言いました。
第3回では「全部無料の代わりに、ここが欠けている」と言いました。

ここから言えることは1つです。**「データグリッドは高機能だからお金が要る」わけではない。**
どこを無料にして、どこで採算を取るのか。それは**そのライブラリの方針の問題**でした。
機能の難しさが値段を決めているのではありません。

部品は15項目中 **無料13 / 有料0 / 無し2**。無いのはコマンドパレットとリッチテキストです。
エコシステム (`@ant-design/charts` `pro-components` `pro-table` `x`) も確認した範囲で
すべて MIT で、**有料版という区分がありません**。

## 7軸の結果

### 軸1 デザイン (採点しない)

[shots/](./shots) の10枚と、他の実装の同じ番号を並べて見てください。点数は付けません。

カレンダーの盤面に既定の差がはっきり出ます。**英語表記** (`Aug 2026`) で**日曜始まり**
(Mantine は月曜始まり)。4実装で唯一、**年送りの二重矢印**と**「Today」ボタン**が既定で付きます。
情報量が多く、業務システム向けという設計思想が既定値に出ています。

### 軸2 開発速度

| | 値 |
|---|---|
| 自作行数 | 286 (`src/App.tsx` 260 + `src/main.tsx` 26) |
| 取り込み行数 | 0 |
| 自作コンポーネント数 | 2 |
| 手数 | 2 |

Mantine (269 行) と MUI (307 行) のあいだで、**書く量では大きな差が出ません**。

1つ注意があります。Ant Design の `Typography.Paragraph` は `<p>` を描画せず `<div>` になります
(`component` を指定しても変わりません)。全実装を同じ手順で計測する都合上、ここだけ
素の `<p>` で囲みました。見た目は変えていません。
**同じ画面を作っても、出てくる HTML は実装ごとに違います。**

### 軸3 自由度 (改造3課題)

| 課題 | 結果 |
|---|---|
| (a) ブランド色1つで全体を差し替え | 可能 / **1箇所・1値** (`token.colorPrimary`) |
| (b) 全部品の角丸を 0 に | 可能 / (a) と同じ1箇所 (`token.borderRadius`) |
| (c) ダイアログの開閉アニメを差し替え | 可能 / (a) と同じ1箇所 (`components.Modal`) |

3課題すべてが `ConfigProvider` の `theme` に収まります。ここは Mantine と同じですが、
**Ant Design は色を1値で渡せます**。Mantine は10段階の配列を要求するので、
1色から濃淡を作る手間がありました。**渡す手間まで含めると、いちばん軽いのは Ant Design です。**

確認は実行時の計算済みスタイルで行い、主ボタンの背景色が指定色 (`rgb(95, 90, 175)`) に、
角丸が `0px` に変わることを見ています。検証後は既定へ戻し、ビルド出力のハッシュ・
gzip 値・行数が改造前と一致することを確かめました。**改造版でキャプチャは撮っていません。**

本文以外の淡い文字が基準に届きません。**5実装のうち2つで同じことが起きました。**

**この回で、計測そのものの欠陥を2つ見つけて直しています。**

1. **別の実装を測っていた。** `npx vite preview` は実行ファイルの解決先を親ディレクトリまで
   遡るため、別の kit の vite が別の kit のフォルダで起動することがありました。
   Ant Design を測ったつもりで shadcn/ui と MUI を測っていた測定が実際に発生しています。
   vite の実体をパスで名指しし、**配信画面が本当にその kit か**を `<title>` で照合してから
   測るようにしました。違えばそこで止まります。

2. **判定が実装依存だった。** 最初「タブが矢印キーで動かない」「Esc で閉じない」と出ましたが、
   **どちらも実際には正しく動いていました**。タブは読み上げ用の文字が混ざって完全一致が外れ
   (`"Tab 2 of 2登録"`)、ダイアログは DOM に残したまま非表示にする方式だったためです。

直したあと**5実装すべてを測り直し、公開済み4実装の値が1つも変わらないこと**を確認しています。
第1〜3回で公開した数字と主張に訂正はありません。

## つまずいた点

**`message` は `App` で包まないと使えません。** `ConfigProvider` の内側に `<App>` を置き、
`App.useApp()` から取り出します。包み忘れると動きません (v5 以降の作法)。

**`Typography.Paragraph` が `<p>` になりません。** `<div>` が出ます。`component` を渡しても
変わりませんでした。段落として意味を持たせたい場合は自分で `<p>` を用意します。

**Select の候補は仮想スクロールです。** 見えている数件しか DOM に存在しません。
自動テストで「候補を名前で探して押す」と、画面外の候補は見つかりません。
打ち込んで絞り込んでから押す必要があります。

**転送量が大きいです。** 5実装で最大の 329.36 kB (gzip)。部品の数と守備範囲を考えれば
納得できる数字ですが、**軽さが要件なら最初に検討する点**になります。

## 動かし方

```bash
cd antd
npm install
npm run dev      # 開発サーバ
npm run build    # 本番ビルド (転送量はこの出力から読んでいます)
npm run preview  # ビルド結果を配信
```

計測とキャプチャはリポジトリ直下から実行します。

```bash
node scripts/measure-a11y.mts antd 4511
node scripts/capture.mts antd 4571
```

**実行前に、他の preview が同じポートを掴んでいないか確認してください。**
掴んでいると別の実装を測ることになります (スクリプト側でも検出して停止します)。
