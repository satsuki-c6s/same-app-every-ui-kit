## Radix の作者たちが作り直した層 (第10回の本題)

第7回の Radix、第9回の Ark に続く「見た目を持たない層」の3つ目です。
Base UI は **MUI・Radix・Floating UI の作者チーム**が合流して作っているライブラリで、
言ってみれば **Radix の作者たちによる作り直し**にあたります。

| | Radix UI (第7回) | Ark UI (第9回) | Base UI (今回) |
|---|---|---|---|
| 部品数 (トップレベル export) | 35 | 52 | 40 |
| 本物のコンボボックス | 無い | ある | **ある** |
| カレンダー | 無い | ある | **無い** |
| ドロワー | 無い | ある | **ある** |
| 15項目の判定 | 無料4 / 無し11 | 無料10 / 無し5 | **無料6 / 無し9** |
| 自作行数 | 597 | 789 | **626** |
| JS 転送量 (gzip) | 98.32 kB | 135.40 kB | **118.58 kB** |
| 導入で増えるパッケージ | 31 | 88 | **9** |
| 対応フレームワーク | React のみ | React / Vue / Svelte / Solid | React のみ |

**部品の広さも行数も転送量も、きれいに Radix と Ark の中間**に入りました。

コンボボックスとドロワーを持つ点は Ark 寄りです。

**キーボード操作は全項目通過**。headless を3つ測って3つとも全通過です。

**新顔の違反が1つ出ました。`aria-dialog-name` — 10実装で初のルールです。**
Base UI のトーストは `role="dialog"` で描画されます。今回のように説明文だけの
トーストを出すと、**名前のないダイアログ**として読み上げ対象になり、axe が指摘します。
他の実装のトーストは status 系のロールなので、この指摘は出ません。
Toast.Title を付ければ名前は付きますが、共通デモの文言は全実装で固定 (説明文のみ) のため、
**既定のまま使うとこうなる**という記録として残します。

**測定スクリプトの誤判定を1件直しました (隠さず記録)。**
最初の計測で「焦点閉じ込め: いいえ」と出ましたが、生の DOM を追うと、Base UI は
**焦点ガードの span を経由して非同期に閉じ込め直す**実装で、Tab 直後に見ると
一瞬だけ外に居るように見えるだけでした。待ってから判定するよう
`scripts/measure-a11y.mts` を直し、**全10実装を測り直して既存9実装の値が
変わらないことを確認**しています (第4回の判定修正と同じ扱い)。

## つまずいた点

**Dialog は Viewport まで組む。** 公式 anatomy は Portal > Backdrop > **Viewport** > Popup。
古い例には Viewport 無しのものもありますが、現行の型に従いました。

**トーストは4点セット。** Provider で包み、Portal + Viewport を置き、
`useToastManager()` の一覧を自分で描画して、はじめて出ます。
出す側も `toastManager.add()` をフックで呼ぶ方式なので、Provider の外では出せません。

**トーストが dialog ロールになる** (軸5参照)。説明文だけで出すと axe に指摘されます。

**焦点閉じ込めの機械判定は「直後に見る」と誤る** (軸5参照)。閉じ込めは正しく効いています。

## 動かし方

```bash
cd baseui
npm install
npm run dev      # 開発サーバ
npm run build    # 本番ビルド (転送量はこの出力から読んでいます)
npm run preview  # ビルド結果を配信
```

計測とキャプチャはリポジトリ直下から実行します。

```bash
node scripts/measure-a11y.mts baseui 4504
node scripts/capture.mts baseui 4503
```

**実行前に、他の preview が同じポートを掴んでいないか確認してください。**
