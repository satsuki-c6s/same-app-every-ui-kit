## 6本ぶんの下に敷かれていた層 (第7回の本題)

Radix UI は**見た目を持たない部品**を配るライブラリです。
第1回の shadcn/ui はこの上に見た目を載せたもので、第6回の Chakra UI も
同系の Ark UI を土台にしています。**7本目にして、下の層を直接測りました。**

**キーボード操作は全項目通りました。** ↓ と Enter でのコンボボックス、
← → でのタブ、Esc と焦点の閉じ込め。初期表示の axe 違反も2件で7実装の最少側です。
これまで「ライブラリを使えば矢印キーは効く」と繰り返してきましたが、
**それを担っていたのはこの層でした。**

代償は行数に出ます。

| | 自作行数 | 内訳 |
|---|---|---|
| baseline (手組み) | 610 | 見た目も動作も全部自分で書く |
| **Radix UI** | **597** | **見た目 (CSS 314 行) は自分で書く。動作は部品が持つ** |
| shadcn/ui | 340 | Radix の上に見た目を載せたものを取り込む (別途 1,472 行) |
| Chakra UI | 332 | Ark UI の上に見た目が載っている |
| Mantine | 269 | 見た目も動作も持つ |

**shadcn/ui との差がそのまま「見た目のぶん」です。**
転送量でも同じで、Radix 98.32 kB に対し shadcn/ui は 139.84 kB。
差の 41.5 kB が、載せた見た目の重さになります。

**キーボード操作は全項目通過**しました。ここがこのライブラリの本領です。

**ただしエラー表示中に `color-contrast` が出ます。原因は配色です。**

Radix は `@radix-ui/colors` という配色パッケージを公式に配っており、今回はその値を
そのまま使いました (`#0090ff` `#e5484d` が公式パッケージ 3.0.0 の値と一致することを確認済み)。
公式ドキュメントは **「9番の色の多くは白い文字を載せる前提で作られている」**と案内しています。

その指針どおりに白文字を載せた箇所が、**3.26:1 と 3.91:1** で AA の 4.5:1 に届きませんでした。
**こちらが選んだ色でも、Radix の部品の問題でもありません。**
公式が配る配色を、公式の指針どおりに使った結果です。

ここまで7本で、**既定の配色が基準を外したのは5実装**になりました
(Mantine・Ant Design・daisyUI・Chakra UI・Radix UI)。
**土台まで降りても、この問題は解決しません。**

## つまずいた点

**Select はあるが Combobox は無い。** 選択肢から選ぶ部品はありますが、
入力しながら絞り込む部品は持ちません。今回は Select で代用しました。

**日付部品が無い。** 素の `<input type="date">` を使っています。
盤面はブラウザ側が描くので、キャプチャには写りません (daisyUI・baseline と同じ)。

**Toast は Provider と Viewport の両方が要る。** `Toast.Provider` で囲み、
`Toast.Viewport` を置いて、その上で `Toast.Root` を出します。3つ揃わないと出ません。

**CSS を書かないと何も見えません。** 当たり前ですが、入れただけでは真っ白です。
`data-state` 属性に当てる形で状態ごとの見た目を書きます。

## 動かし方

```bash
cd radix
npm install
npm run dev      # 開発サーバ
npm run build    # 本番ビルド (転送量はこの出力から読んでいます)
npm run preview  # ビルド結果を配信
```

計測とキャプチャはリポジトリ直下から実行します。

```bash
node scripts/measure-a11y.mts radix 4801
node scripts/capture.mts radix 4803
```

**実行前に、他の preview が同じポートを掴んでいないか確認してください。**
