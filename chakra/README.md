## 看板は本当か (第6回の本題)

Chakra UI は公式サイトが「アクセシブルな React アプリを作るための部品」と掲げています。
5本かけて `color-contrast` の未達が3実装で出たので、**その主張が実測で裏付くか**を見ました。

**答えは「おおむね本当。ただし穴がある」でした。**

| | 初期表示 | エラー表示中 |
|---|---|---|
| baseline / shadcn/ui / MUI | 2 | 2 |
| **Chakra UI** | **2** | **3** |
| Mantine / Ant Design / daisyUI | 3 | 3 |

初期表示は2件で、`color-contrast` は出ません。キーボード操作も全項目を満たします。
Mantine・Ant Design・daisyUI が既定の淡色で引っかかっていた場所を、Chakra は通ります。

**ところがフォーム検証エラーを出すと3件に増えます。** 増えた1件は `color-contrast` で、
原因は**公式の `Field.ErrorText` の既定色**です。白背景に `#ef4444` で **3.76:1**、
WCAG AA の 4.5:1 に届きません。**こちらが指定した色ではありません。**

つまり、**平常時は基準を満たすのに、エラーを出した瞬間に外れる**。
しかも外れるのは「入力を直してください」と伝える、**いちばん読ませたい文字**です。

**6実装のうち4つで、既定の色が基準を外していました。**
アクセシビリティを掲げている実装でも、掲げていない実装でも起きています。
**既定値は最後の砦ではない**、というのがこの回の結論です。

| | 値 |

**6実装で最多**でした。daisyUI (331 行) とほぼ同じですが、理由が違います。
daisyUI は「持っていない部品を自分で書いた」ぶんでしたが、Chakra は
**部品を細かい部分に分けて組む設計**なので、同じ画面でも行数が伸びます。

`Select.Positioner` `Select.Content` `Select.Item` … と積み上げます。
**融通は利きますが、書く量は増えます。**

### 軸3 自由度 (改造3課題)

| 課題 | 結果 |
|---|---|
| (a) ブランド色1つで全体を差し替え | 可能 / 1箇所。ただし**11段階 + 7項目** |

3課題とも可能で、場所は `createSystem` の1箇所です。
**ただし渡す値の量が6実装で最も多くなりました。**

Mantine の10段階より重く、Ant Design や daisyUI の「1値」とは大きな差です。

**「1箇所で済む」ことと「1値で済む」ことは別**という第3回の指摘が、ここで最も極端に出ました。

角丸が `0px` に変わることを見ています。検証後は既定へ戻して行数の一致を確かめました。
**改造版でキャプチャは撮っていません。**

## つまずいた点

**`Field` を使わないと `label` 違反が出ます。** はじめ `Text as="label"` で組んでいたら
入力欄と紐付かず、axe に指摘されました。公式の `Field.Root` / `Field.Label` を使うと
自動で紐付きます。**入力欄は必ず `Field` で囲むのが正解です。**

**`id` を自分で指定すると紐付けが切れます。** `Field` は入力欄に自動で id を振って
ラベルの `for` をそこへ向けます。こちらで `id` を上書きすると食い違うので、
その場合は `Field.Label` に `htmlFor` も渡して合わせる必要があります。

**日付部品のドキュメントが「Not available」と出ます。** ページはあるのに部品が無いように
見えますが、**インストールしたパッケージには実装されています**。
公式サイトの表示だけで判断すると、あるものを無いと数えてしまいます (実際に一度やりました)。

**ダークモードは class 名で切り替えられます。** 公式手順では `next-themes` を足す形が
案内されていますが、`dark` / `light` の class を付けるだけでも動きます
(こちらも公式ドキュメントに載っている手段)。依存を増やしたくない場合はこちらで足ります。

## 動かし方

```bash
cd chakra
npm install
npm run dev      # 開発サーバ
npm run build    # 本番ビルド (転送量はこの出力から読んでいます)
npm run preview  # ビルド結果を配信
```

計測とキャプチャはリポジトリ直下から実行します。

```bash
node scripts/measure-a11y.mts chakra 4761
node scripts/capture.mts chakra 4772
```

**実行前に、他の preview が同じポートを掴んでいないか確認してください。**
掴んでいると別の実装を測ることになります (スクリプト側でも検出して停止します)。
