## 送っていないぶん、動作を持っていない (第5回の本題)

daisyUI は **CSS のクラス名だけを配るライブラリ**です。JavaScript を1バイトも足しません。
その結果が、そのまま数字に出ました。

| | JS 転送量 (gzip) | 矢印キー操作 |
|---|---|---|
| baseline (手組み) | 64.12 kB | できない |
| **daisyUI** | **64.36 kB** | **できない** |
| shadcn/ui | 139.84 kB | できる |
| Mantine | 143.04 kB | できる |
| MUI | 211.49 kB | できる |
| Ant Design | 329.36 kB | できる |

**軽さと、正しく作るのが難しい部分は、引き換えの関係にあります。**

矢印キーで候補を動かす、選択中の項目を読み上げに伝える、といった動作はすべて
JavaScript が要ります。daisyUI は持っていないので、**使う側が書くことになります**。
これは欠陥ではなく設計です。何にお金と容量を払うかという選択の問題です。

個人開発や社内ツールで見た目だけ整えたいなら、この軽さは効きます。
公共・教育・大企業向けでキーボード操作が要件に入るなら、自分で書く覚悟が要ります。

## 7軸の結果

### 軸1 デザイン (採点しない)

[shots/](./shots) の10枚と、他の実装の同じ番号を並べて見てください。点数は付けません。

**`08-calendar.png` に注目してください。盤面がどこにも写っていません。**
daisyUI はカレンダーを持たないので素の `<input type="date">` を使っており、
盤面はブラウザ (と OS) が描いてページの中に存在しないためです。
第1回の baseline とまったく同じ現象で、**他の4実装では全部写っていました**。

### 軸2 開発速度

| | 値 |
|---|---|
| 自作行数 | 331 (`src/App.tsx` 301 + `src/main.tsx` 23 + `src/index.css` 7) |
| 取り込み行数 | 0 |
| 自作コンポーネント数 | 2 |
| 手数 | 3 |

**ライブラリを使った5つのなかでは最多**でした。理由は明快で、
**コンボボックスの候補リストを自分で書いている**ためです。daisyUI が持たないので、
第1回の baseline と同じ手で組みました。
**「持っていない部品のぶんだけ、書く量が増える」**が数字に出ています。

それでも baseline の 610 行より 279 行少ないのは、見た目の CSS を書かずに済むからです。
**見た目は速くなる。動作は速くならない。**これが daisyUI の位置づけです。

### 軸3 自由度 (改造3課題)

| 課題 | 結果 |
|---|---|
| (a) ブランド色1つで全体を差し替え | 可能 / **1箇所・1値** (`--color-primary`) |
| (b) 全部品の角丸を 0 に | 可能 / (a) と同じ1箇所。ただし**3値**を指定 |
| (c) ダイアログの開閉アニメを差し替え | **新規に書く必要あり** (公式の口が無い) |

(a)(b) は CSS の `@plugin "daisyui/theme"` 1箇所で済みます。色は1値で渡せます。
ただし角丸は `--radius-field` `--radius-box` `--radius-selector` の**3値**を指定します
(入力欄・箱・選択肢で別々に持っているため)。

**(c) は baseline と同じ「新規に書く必要あり」**でした。公式ドキュメントには位置
(`modal-bottom`) や開き方の選択肢はありますが、**開閉アニメを差し替える公式の口が
示されていません**。JavaScript を持たないライブラリなので、動きに関わる部分は自前です。

確認は実行時の計算済みスタイルで行い、主ボタンの背景色が指定色 (`rgb(95, 90, 175)`) に、
角丸が `0px` に変わることを見ています。検証後は既定へ戻し、ビルド出力のハッシュ・
gzip 値・行数が一致することを確かめました。**改造版でキャプチャは撮っていません。**

### 軸4 技術構成 (2026-08-02 取得)

| 項目 | 値 |
|---|---|
| 対応フレームワーク | **選ばない** (React / Vue / Svelte / Angular / 素の HTML) |
| SSR | 対応 |
| React Server Components | **動く** (クライアント側の JavaScript が無いため) |
| スタイルの仕組み | Tailwind CSS プラグイン (クラス名のみ) |

**ここが5実装で唯一の特徴です。** 他の4つはすべて React 専用ですが、
daisyUI は CSS だけなので**フレームワークを選びません**。
RSC でもそのまま動きます。JavaScript を持たないことが、ここでは強みになります。

### 軸7 必要な部品

15項目中 **無料10 / 有料0 / 無し5**。ただし**この「無料」は意味が違います**。

daisyUI の「ある」は**見た目のクラスがある**という意味で、
**動作を持っているとは限りません**。

| 種類 | 例 |
|---|---|
| 見た目だけ (動作は自作) | テーブル (並べ替え)、トースト (出し入れ)、ページネーション (ページ送り) |
| ブラウザの機能に乗る | ダイアログ (`<dialog>`)、フォーム検証、日付入力 |
| 別ライブラリ前提 → **無し**と判定 | カレンダー (Cally 等)、グラフ (ApexCharts) |
| 本当に無い | データグリッド、コンボボックス、コマンドパレット、リッチテキスト |

**「別ライブラリにスタイルを当てる方法がある」ことは、持っていることとは違います。**
公式が案内していても、導入するのは別のライブラリだからです。

## つまずいた点

**`datalist` では計測できませんでした。** はじめコンボボックスを素の
`<input list>` + `<datalist>` で組みましたが、**候補が DOM に出ません** (ブラウザが描くため)。
全実装を同じ手順で操作・計測できなくなるので、第1回の baseline と同じく
**候補リストを自分で描く**方式に変えました。

**タブはラジオボタン方式です。** 公式は `<input type="radio">` に `tab` クラスを当てる形を
案内しています。JavaScript を持たないので、これで状態を保持します。
ただし**矢印キーでの切り替えは付いてきません**。

**テーマは CSS に書きます。** 設定ファイルではなく、`@plugin "daisyui"` を CSS に書く方式です
(daisyUI 5 から)。古い記事の `tailwind.config.js` に書く手順は通りません。

## 動かし方

```bash
cd daisyui
npm install
npm run dev      # 開発サーバ
npm run build    # 本番ビルド (転送量はこの出力から読んでいます)
npm run preview  # ビルド結果を配信
```

計測とキャプチャはリポジトリ直下から実行します。

```bash
node scripts/measure-a11y.mts daisyui 4611
node scripts/capture.mts daisyui 4612
```

**実行前に、他の preview が同じポートを掴んでいないか確認してください。**
掴んでいると別の実装を測ることになります (スクリプト側でも検出して停止します)。
