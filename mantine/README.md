## 「全部無料」の意味 (第3回の本題)

第2回の MUI では、無料の Community と有料の X Pro の境目が話の中心でした。
Mantine には**その境目がありません**。

2026-08-02 時点で公式が出している 10 パッケージを調べたところ、
`core` `hooks` `dates` `notifications` `form` `charts` `spotlight` `tiptap` `dropzone` `carousel`
は**すべて 9.5.0 / MIT** でした。機能を制限した無料版と、解除する有料版という構造がありません。

そのため、**MUI に無かった3つを Mantine は無料で持ちます**。

| 部品 | MUI | Mantine |
|---|---|---|
| コマンドパレット | 無し | 無料 (`@mantine/spotlight`) |
| フォーム検証 | 無し (表示のみ・機構は別ライブラリ) | 無料 (`@mantine/form`) |
| ファイルアップロード | 無し | 無料 (`@mantine/dropzone`) |
| リッチテキスト | 無し | 無料 (`@mantine/tiptap`) |

**代わりに欠けているのがデータグリッドです。** `Table` に固定見出し (`stickyHeader`) はありますが、
仮想化も列固定も持ちません。MUI では有料の X Pro が担当していた領域が、Mantine では
**有料でもなく、無料でもなく、単に無い**という形になります。

よく名前の挙がる `mantine-datatable` は**公式ではなく第三者製**です。混同すると
「公式が持っている」と誤解するので、この表では「無し」と判定しました。

**大量データの表が要件の中心なら、Mantine 単体では埋まりません。** ここは正直に言う必要があります。

## 7軸の結果

### 軸1 デザイン (採点しない)

[shots/](./shots) の10枚と、他の実装の同じ番号を並べて見てください。点数は付けません。

見た目で分かる違いを1つだけ挙げると、**カレンダーの盤面が既定で英語**です
(`Mo Tu We` / `August 2026`)。画面の他の文言は日本語なのでここだけ浮きます。
日本語化はできますが、**既定値のみルールに従って既定のまま撮っています**。

### 軸2 開発速度

| | 値 |
|---|---|
| 自作行数 | **269** (`src/App.tsx` 240 + `src/main.tsx` 29) |
| 取り込み行数 | 0 |
| 自作コンポーネント数 | 2 |
| 手数 | 2 |

**4実装で最少です。** MUI より 38 行少ないのは、トーストとダイアログの扱いが軽いためです。
MUI は `Snackbar` の中に `Alert` を入れ、開閉の状態も自分で持ちます。
Mantine は `notifications.show()` の1行で、状態を持ちません。

逆に**並べ替え付きの表見出しは Mantine に無い**ので、そこは `UnstyledButton` で自分で書いています。
「部品が多い = 書く量が減る」とは限らず、**どの部品を持っているかで決まります**。

### 軸3 自由度 (改造3課題)

| 課題 | 結果 |
|---|---|
| (a) ブランド色1つで全体を差し替え | 可能 / 1箇所 (`createTheme`) |
| (b) 全部品の角丸を 0 に | 可能 / (a) と同じ1箇所 (`defaultRadius`) |
| (c) ダイアログの開閉アニメを差し替え | 可能 / (a) と同じ1箇所 (`components.Modal.defaultProps.transitionProps`) |

**3課題すべてが `createTheme` の呼び出し1つに収まりました。** ダイアログのアニメまで
同じテーマ定義の中で指定できるのはこの実装だけです。

ただし (a) には注意があります。**Mantine の色は10段階の配列で渡す規約**なので、
「ブランド色1つ」をそのまま渡せません。1色から10段階を作る手間が要ります。
**「1箇所で済む」ことと「1値で済む」ことは別です。**

確認は実行時の CSS 変数で行い、`--mantine-radius-default` が `0rem` に、
`--mantine-primary-color-filled` が指定色に変わることを見ています。
検証後に既定へ戻し、**ビルド出力のハッシュ・gzip 値・行数が改造前と一致すること**を確認済みです。
改造版でキャプチャは撮っていません。

### 軸4 技術構成 (2026-08-02 取得)

| 項目 | 値 |
|---|---|
| 対応フレームワーク | React のみ |
| SSR | 対応 (Next.js 向けの公式手順あり) |
| React Server Components | 部品は client 側。RSC としては動かない |
| スタイルの仕組み | **素の CSS (CSS モジュール + CSS 変数)** |

**MUI との一番の設計差がここです。** MUI は CSS-in-JS でスタイルを JS に含めますが、
Mantine 7 以降はスタイルを CSS ファイルとして持ちます。
だから Mantine は CSS 転送量が 37.12 kB と4実装で最大になり、MUI は CSS が 0 になります。
**「どちらのファイルに乗るか」の違い**なので、JS の数字だけを並べて比べると判断を誤ります。

JS と CSS を足すと Mantine 180.16 kB / MUI 211.49 kB です。

| 項目 | 値 |
|---|---|
| axe 違反 初期表示 | 3 (`color-contrast` / `landmark-one-main` / `region`) |
| axe 違反 ダイアログ表示中 | 2 (`color-contrast` / `region`) |
| axe 違反 フォーム検証エラー中 | 3 |
| Tab で主要5操作に到達 | 完遂 |
| ↓ と Enter でコンボボックスを選べる | できる |

| ダイアログの焦点閉じ込め | はい |
| Esc でダイアログが閉じる | はい |

キーボード操作は全項目を満たします。ここは shadcn/ui・MUI と同じで、差は出ません。

**差が出たのは自動検査です。4実装で Mantine だけ1件多く出ました。**
増えた分は `color-contrast` で、**22 箇所すべてが既定の淡色トークン `dimmed`** です。
白背景に `#868e96` で **3.32:1**、WCAG AA の 4.5:1 に届きません。
他の3実装で同じ用途に使った淡色 (MUI の `text.secondary` など) は基準を満たしていました。

**こちらが色を触った結果ではありません。既定値のまま使うと出ます。**
説明文・補足行・件数表示のような「本文以外の文字」に使う色なので、
既定のまま作ると、そういう文字がまとめて基準を外れます。

**ダイアログ表示中に 0 にならないのも Mantine だけ**です。他の3実装は背後が走査対象から
外れて 0 になりますが、Mantine のモーダルでは背後の要素が残ります。

**閉じるボタンの `aria-label` は公式ドキュメントの指示どおり設定して測っています。**
Mantine の `Modal` と `Notification` は閉じるボタンを既定で出しますが、名前は自動では付きません。
公式が `closeButtonProps` で設定するよう明記しているため、設定した状態を正式な計測値としました
(設定前は `button-name` が追加で出ています)。**この経緯を隠さず残します。**

## つまずいた点

**スタイルの読み込み順に決まりがあります。** `@mantine/core/styles.css` を先に読み、
そのあとに `dates` と `notifications` の CSS を読みます。順番を変えると崩れます。

**`Notifications` は子要素を取りません。** `<Notifications>{children}</Notifications>` と書くと
画面が空になります。`MantineProvider` の中に**兄弟として置く**のが正しい形です。

**公式 Vite 手順の `postcss-preset-mantine` は入れていません。** これは自分で CSS を書いて
Mantine のミックスインを使う場合に要るものです。今回は独自の CSS を1行も書いていないため
不要でした。**入れなくてもビルドは通り、共通デモは9要件すべて動きます。**

**並べ替え付きの表見出しがありません。** `Table` は素直な表で、見出しのボタン・矢印・
`aria-sort` は自分で用意します。MUI の `TableSortLabel` に相当する部品はありません。
